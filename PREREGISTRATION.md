# Preregistration -- operating-envelope k=2 base camp (v0.3-rc5)

An externally timestamped preregistration commit fixes, before any validation data is
generated, everything that could otherwise be tuned to a result: the estimator, the gate
rule and thresholds, the seed partition, the debiasing choice (identity only), the
generator cell table, the runtime environment, and the execution order.

## What is tested

Primary: does the frozen estimator pass the construction-null bias-amplitude equivalence
gate (Tier-0a; Student-t Bonferroni simultaneous CI) at B=500, k=2, n=128, across pi_max
in {low,med,high}? Secondary (only if Tier-0a passes): the k=2 Tier-1 envelope. Identity
debiasing only; Tier-1 is generated only if Tier-0a passes.

## rc5 integrity hardening (scientific core unchanged)

- Package closure is exact: `git ls-tree -r HEAD` must equal the `SHA256SUMS.txt`
  target set plus `SHA256SUMS.txt` itself. Extra tracked files, un-hashed subdirectories,
  duplicate/hash-malformed targets, symlinks, and recursive stray files fail closed.
- `commit_url` must have the canonical path `/<owner>/<repo>/commit/<commit_sha>`. A SHA
  appearing only in a query, fragment, or unrelated path is rejected.
- Any pre-existing `._oe_stage_*` path is rejected before START.
- Completion checks are run on CSVs after serialization and re-read. All replicate-level
  `S_R, S_RZ, S_CR, S_CRZ, G0, G1, M_gbm, M_tilde` values must be present and finite;
  identity debiasing and both four-score identities must hold; null diagnostics must have
  exactly three rows with bounded decomposition residuals; and every saved Tier-0 field is
  recomputed from raw replicates. COMPLETE is written only after all checks pass.

## Workflow (strict order)

1. Clone this package into a **dedicated** repository.
2. In the **exact environment that will run validation**, run
   `python oe_v03_run.py --writeenv`. It locks `env_lock.json` and regenerates
   `SHA256SUMS.txt`, and prints `package_sha256 = sha256(SHA256SUMS.txt)`.
3. Inspect `git status`, then `git add -A && git commit` the package files (the
   `.gitignore` keeps proof/markers/pycache/staging out). The tracked set must be exactly
   the SHA target set plus `SHA256SUMS.txt`; do not commit any extra file or subdirectory.
   Push. This is the **externally timestamped preregistration commit**.
4. Create a third-party time record of this exact commit/package: Zenodo deposit, OSF
   registration, or GitHub Release (server `published_at`).
5. **Manually verify** the external record points at this exact commit and at
   `package_sha256 = sha256(SHA256SUMS.txt)`. The runner checks format only.
6. Create `PREREGISTRATION_PUSHED.json` (untracked; ignored by `.gitignore`):
   ```json
   {
     "commit_url": "https://github.com/<owner>/<repo>/commit/<HEAD>",
     "commit_sha": "<HEAD, 40/64 hex>",
     "package_sha256": "<sha256(SHA256SUMS.txt), 64 hex>",
     "timestamp_evidence_url": "https://zenodo.org/records/<id>  (or osf.io / github.com)",
     "timestamp_evidence_type": "zenodo | osf | github_release",
     "timestamp_utc": "<ISO-8601 UTC>"
   }
   ```
7. `python oe_v03_run.py --preflight` -- all guards must PASS (offset-free).
8. `python oe_v03_run.py --run` -- claims the bank atomically, runs validation once.
   Construction-null cells first; Tier-1 only if Tier-0a passes.
9. Commit the results (validation CSVs, TIER0_RESULT.json) as a **second** commit; its
   external time record must post-date step 4's.

Nothing in the preregistration commit may change after step 3. `--preflight` also
refuses any stale `._oe_stage_*` path. **Crash-burn:** an interrupted `--run` (START
present, COMPLETE absent) consumes the bank; do not resume, delete the lock, or reuse a
staged directory. A new attempt needs a fresh unexposed bank, manifest, hash, timestamp,
and an explicit aborted record (e.g. v0.3.1).

Note: `package_sha256` is defined as `sha256(SHA256SUMS.txt)` -- a content commitment to
the entire package -- computed after `--writeenv`, not the transport-zip hash.

## Epistemic grade

Unsigned, third-party-timestamped preregistration. The external record attests this
content existed before validation; it does not cryptographically attest the author's
private state.
